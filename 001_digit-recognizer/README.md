## 1. コンペティションの目的
- **コンペ名:** [Digit Recognizer](https://www.kaggle.com/competitions/digit-recognizer)（Kaggle公式）
- **目的:** 28×28ピクセルの白黒手書き数字画像（0〜9）を見て、コンピュータが自動で「どの数字が書かれているか」を正しく判別する仕組みを作ることです。
- 機械学習の分野では、これを **「多クラス画像分類（Multi-class Classification）」** と呼びます。

---

## 2. 予測する値
- **予測する対象:** 各テスト画像に描かれている **`0` から `9` までの整数値（Label）** です。
- 例: 画像に「7」と書かれていれば、予測値は `7` です。

---

## 3. データの構造と専門用語の解説

### データの構成
| ファイル名 | 行数（データ数） | 列数 | 内容 |
|---|---|---|---|
| **`train.csv`**（学習用データ） | 42,000行 | 785列 | 画像データ（784列）＋ **正解ラベル（`label` 列）** |
| **`test.csv`**（テスト用データ） | 28,000行 | 784列 | 画像データ（784列）のみ（正解ラベルなし） |
| **`sample_submission.csv`** | 28,000行 | 2列 | 提出用CSVファイルのひな形（見本） |

### 専門用語のやさしい解説
- **特徴量（Feature / とくちょうりょう）:**
  - 予測の手がかりになる情報のことです。
  - 今回は、手書き画像（縦28ピクセル × 横28ピクセル ＝ 合計784ピクセル）の各点における濃淡の数値（`pixel0` から `pixel783`）が特徴量です。各ピクセルは `0`（真っ白・背景）から `255`（真っ黒・文字）の数値で表されます。
- **目的変数（Target / もくてきへんすう / 正解ラベル）:**
  - モデルが当てようとする「答え」のことです。今回は `label` 列（0〜9）がこれに当たります。
- **訓練データ（Train Data）とテストデータ（Test Data）:**
  - **訓練データ（教科書）:** 正解ラベルが付いており、モデルが「この形の時は数字の3だ」と学習するために使います。
  - **テストデータ（本番試験）:** 正解ラベルが付いておらず、モデルが自力で答えを予想するためのデータです。
- **ベースライン（Baseline）:**
  - 改善の土台となる「最初のシンプルで確実なモデル」のことです。いきなり複雑な手法を使わず、まずベースラインを作ることで、その後の工夫でどれだけ予測精度が上がったかを公平に比較できます。

## 4. 評価方法（Evaluation Metric）とその意味

### 評価指標: 正解率（Categorization Accuracy）
本コンペティションの成績（リーダーボード順位）は、**正解率（Accuracy / アクセラシー）** だけで決まります。

$$\text{正解率 (Accuracy)} = \frac{\text{モデルが正しく当てられた画像の枚数}}{\text{テスト画像の全枚数（28,000枚）}}$$

- **意味:**
  - `1.0`（100%）: 28,000枚すべて正解。
  - `0.95`（95%）: 28,000枚中、26,600枚正解し、1,400枚間違えた。
- **統計検定とのつながり:**
  - 統計検定2級などで学ぶ **「混同行列（Confusion Matrix）」** において、対角成分（正解した件数）の合計を全データ数で割った値と一致します。
  - 0から9までの各数字がほぼ同じ割合で含まれているため、正解率はモデルの性能を直感的に評価するのに適しています。

## 5. 提出形式（Submission Format）

Kaggleにアップロードする提出ファイルは、以下の条件を満たした **CSV形式** である必要があります。

- **ファイル形式:** `.csv`
- **1行目（ヘッダー）:** `ImageId,Label`
- **2行目以降（28,000行）:** `1` から `28000` までの連番と、予測した数字（0〜9）

```csv
ImageId,Label
1,2
2,0
3,9
...
28000,7
```

## 6. 主なルールと禁止事項

詳細は [rules-ja.md](rules-ja.md) を参照してください。特に重要な点は以下の通りです：

1. **1人1アカウント:** 複数アカウントでの参加・提出は禁止です。
2. **非公開共有の禁止:** チーム外の誰かと個人的にコードやデータをやり取りしてはいけません（公開Notebookでの共有はOK）。
3. **手作業ラベリングの禁止:** テスト画像を目で見て人間が手動でラベルを入力する行為は禁止です。
4. **外部流出ラベルの直接利用禁止:** インターネット上にあるMNISTの正解をそのまま貼り付けて提出する行為は禁止です。
5. **提出回数制限:** 1日 **最大10回まで** 提出できます（UTC 0時 / 日本時間 午前9時にリセット）。
